# Provenance

This directory contains a knowledge graph of the [Boulder](https://github.com/letsencrypt/boulder) ACME Certificate Authority, generated by the [understand-anything](https://github.com/Lum1104/Understand-Anything) plugin. The graph describes Boulder's architecture, not this `boulder-development` docs repo.

For how to query and use the graph, see [`USAGE.md`](./USAGE.md).

## Source

- Repository: `letsencrypt/boulder` (upstream)
- Commit: `3647aeed1eb896ea0d96e645d9e54b22c33373d7` ("build(deps): bump actions/github-script from 8 to 9 (#8742)")
- Analysis date: 2026-05-04 (UTC)

## Tooling

- Skill: `/understand` (understand-anything plugin v2.5.1)
- Runtime: Node.js v25.9.0, pnpm 10.15.1
- Validation path: `--review` (full LLM graph reviewer)

## Corpus scope

327 files analyzed out of 1,030 in the working tree (-476 via `.understandignore`, -227 via built-in ignore defaults). The corpus intentionally excludes:

- `vendor/` (Go dependencies)
- `*_test.go` (unit tests — 163 files)
- `*.pb.go` (generated gRPC stubs — 22 files)
- `test/` (integration harness, fixtures — 235 files)
- `mocks/` (test doubles)
- `linter/lints/**/*.{pem,json}` and `linter/lints/test/` (lint fixtures)
- `iana/data/` (static IANA special-use domain lists)
- `tools/` (build/release scripts)
- `go.sum` and miscellaneous metadata (CODEOWNERS, `.dockerignore`, `.golangci.yml`, dependabot, issue template)

Kept: all production Go services and libraries, all `.proto` schemas, all `.sql` migrations, Dockerfiles / `docker-compose*.yml`, GitHub Actions workflows, `data/` email templates, `ratelimits/testdata/` YAML fixtures (they document the rate-limit schema), and all architecture docs under `docs/`.

## Graph shape

- 1,620 nodes (253 file, 246 class, 1,005 function, 42 table, 29 config, 22 document, 12 schema, 8 pipeline, 2 service)
- 3,340 edges (1,293 contains, 1,200 imports, 732 exports, 16 documents, 10 defines_schema, 4 triggers, 8 related, 1 depends_on)
- 10 layers: Web Frontend, Orchestration (RA), Identifier Validation, Certificate Issuance, Storage (SA + DB), Publication & Revocation, Supporting Services, Binary Entry Points, Shared Libraries, Infrastructure & Ops
- 12 tour steps tracing the full ACME issuance lifecycle

## Build notes

- One Phase 2 batch (`cmd-2`) hit an API error on first dispatch and was retried once to completion.
- The graph reviewer applied 37 ID-prefix corrections post-review where subagents had emitted `file:` IDs on nodes whose `type` was `config`, `document`, or `schema` (testdata fixtures, README files, `.proto` definitions). These were rewritten in-place before save.
- `fingerprints.json` is a tree-sitter baseline over the 327-file corpus from this commit. Useful only if `/understand` is re-run against the same Boulder checkout.

## Regenerating

```bash
cd /path/to/boulder
cp /path/to/boulder-development/.understand-anything/.understandignore .understand-anything/
# Launch /understand --review in Claude Code from the Boulder checkout root
# Then regenerate ONBOARDING.md from the new graph: /understand-onboard
```

Expect ~15-20 minutes on a warm machine; most time is spent on LLM-driven semantic analysis in Phase 2.
